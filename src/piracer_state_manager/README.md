# piracer_state_manager

ROS 2 state manager consuming target-filtered suitcase Detection2DArray messages. Its internal behavior state is SEARCH, ACQUIRE, or FOLLOW. It publishes `/piracer/state/run`, a Bool indicating that the manager is enabled and the detector stream is fresh. It starts false and becomes equal to the manager's enabled state after a valid, strictly newer detector message; it does not indicate that a target was detected. Operation starts automatically in SEARCH after the first valid detector result. The internal behavior state is not published on a ROS topic.

The `/piracer/state/enable` SetBool service only enables or stops the manager; enabling restarts the internal state at SEARCH. The manager coordinates `/search/enable`, `/acquire/enable`, and `/follow/enable`, disabling the other behaviors before enabling the selected one. The current state-machine safeguard holds the state at SEARCH. Search remains operational; Acquire and Follow are service scaffolds that acknowledge disable requests and reject enable requests as not implemented. The manager does not publish movement or gate commands, or verify a physical stop. The `/piracer/state/run` output reflects manual enable AND a fresh detector stream.

Run `ros2 launch piracer_state_manager search_state_manager.launch.py` to co-launch Search and the state manager with all three behavior service servers. The `search_enable_service` launch argument configures the shared endpoint and defaults to `/search/enable`. `ros2 launch piracer_state_manager state_manager.launch.py` starts the manager, Acquire and Follow service nodes; it expects Search to be launched separately. Other startup parameters are in `config/state_manager.yaml`. The `/piracer/state/enable` SetBool service accepts false to latch manual stop and true to restart in SEARCH.
