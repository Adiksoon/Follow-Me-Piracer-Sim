# piracer_state_manager

ROS 2 state manager consuming target-filtered suitcase Detection2DArray messages. Its internal behavior state is SEARCH, ACQUIRE, or FOLLOW. It publishes `/piracer/state/run`, a Bool indicating that the manager is enabled and the detector stream is fresh. It starts false and becomes equal to the manager's enabled state after a valid, strictly newer detector message; it does not indicate that a target was detected. Operation starts automatically in SEARCH after the first valid detector result. The internal behavior state is not published on a ROS topic.

The `/piracer/state/enable` SetBool service only enables or stops the manager; enabling restarts the internal state at SEARCH. The manager coordinates `/search/enable`, `/acquire/enable`, and `/follow/enable`, disabling the other behaviors before enabling the selected one. The current state-machine safeguard holds the state at SEARCH. Search remains operational; Acquire is still a service scaffold that acknowledges disable requests and rejects enable requests as not implemented. `piracer_follow` subscribes to `/yolo/detections` and `/piracer/follow/target_point`. When enabled, it transforms a fresh target point into `base_link`, applies provisional P distance and direction control, and publishes bounded `Twist` commands on `/cmd_vel`; invalid, stale, missing, or untransformable targets produce zero commands. The direction output is converted through the active Ackermann wheelbase and steering-angle bound. The control type and gains are explicitly provisional and require tuning experiments. The node does not consume Nav2 goals or autonomously switch to Nav2. The `/piracer/state/run` output reflects manual enable AND a fresh detector stream.

Run `ros2 launch piracer_state_manager search_state_manager.launch.py` to co-launch Search and the state manager with all three behavior service servers. The `search_enable_service` launch argument configures the shared endpoint and defaults to `/search/enable`. `ros2 launch piracer_state_manager state_manager.launch.py` starts the manager, Acquire and Follow nodes; it expects Search to be launched separately. Follow uses simulation time through the `follow_use_sim_time` launch argument, which defaults to false in `state_manager.launch.py` and is forwarded from `use_sim_time` by `search_state_manager.launch.py`. Other startup parameters are in `config/state_manager.yaml`. The `/piracer/state/enable` SetBool service accepts false to latch manual stop and true to restart in SEARCH.
